# demo-seed-six-months — datos demo a 6 meses, categorías de test fuera del form, seed rápido

Extiende la ventana de datos sintéticos del demo de 3 a 6 meses, saca del listado de categorías las filas sembradas por specs/e2e, ordena la carga (mes actual → resto → depuraciones) y cierra fugas del cascade de borrado demo.

## Specs

- S1 (L2): "explorar la opcion de extender la generacion de los datos sintenticos a 6 meses, ya que los reportes como en gastos evitables, no se refleja como debe ser, por el periodo corto de los datos." → ventana del plan: 180 días; rolling window de meses: actual + 5 anteriores.
- S2 (L3, decisión): "Para los reportes que se tiene actualmente, cual seria el periodo de datos, para que los reportes puedan servir para una toma de datos." → respuesta: 6 meses calendario; la densidad de transacciones se mantiene por-mes (los conteos absolutos actuales escalan ×2 o pasan a por-mes) para que el dataset de 180 días no quede ralo.
- S3 (L4): "descarta datos en categoria como Comida E2E, semilla uno, semilla dos, global spec_globlal_key, que son visibles en el form" → `GET /categories` no devuelve filas sembradas por tests (`e2e-*`, `spec_*`) a workspaces reales/demo; los e2e que las usan las siembran con scope de workspace o las limpian, y existe limpieza de las filas globales ya fugadas.
- S4 (L4): "Optimizar la carga de los datos, cargando el mes actual primero, luego el resto y finalmente las depuraciones, para que el usuario no espere mucho tiempo cuando se carge el perfil demo." → orden del seed async: bootstrap → mes 0 → meses -1..-5 → sweep/depuraciones al final; sin wipe innecesario en workspace nuevo.
- S5 (L4): "cuando se depura el workspace, ya sea al inicio o al cerrar sesion, todos los datos generados en ese workspace se eliminan" → el cascade de borrado cubre todas las tablas con workspaceId, incluidas `voices_voice_notes`, `voices_voice_consents` y `reports_period_closes` (hoy faltan). Incluye `receipts_receipt_scans` (L7).
- S6 (L10, corregido L12): "la data de meses anteriores no estan cerrados" → el seed siembra cierres de período **solo para los tres meses más antiguos** (-3..-5); el mes actual y los dos más recientes quedan abiertos/provisionales, como un usuario real que cierra el mes al terminarlo.
- S7 (L11): "el usuario demo, no pueda cambiar su clave, para ello la podemos ocultar y desactivar" → en sesión demo la opción de cambio de clave se oculta y/o desactiva (cliente) y el backend la bloquea si aplica.
